## 1. 项目概述

### 1.1 背景

本项目为**信息集成管理系统**:统一接入并整合多源信息、集中管理业务数据,并对外提供统一的操作界面与 API;用户体系支持本地账号、AD 域(LDAP)与 OIDC 统一身份认证,并具备 RBAC 权限、数据范围与部门级管理能力。

### 1.2 数据源:Baserow

业务数据承载在 **Baserow**(开源在线表格/数据库)中,系统通过其 REST API 在 Web 端**可视化展示与编辑**。Baserow 部署配置见 `deploy/baserow/`。

### 1.3 目标与阶段性(均已完成)

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 一 | 前后端基础框架 + 用户名密码登录 | ✅ |
| 二 | RBAC:权限点、角色、数据范围(all/dept/self) | ✅ |
| 三 | AD 域登录(LDAP)与 OIDC 统一身份认证 | ✅ |
| 四 | 部门配置化 + 主管部门级管理 | ✅ |
| 五 | Baserow 数据源接入与数据看板(展示+编辑+可视化) | ✅ |
| 六 | 在线用户、用户头像、离线部署打包 | ✅ |

## 2. 技术选型

### 2.1 后端:FastAPI

| 备选 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- |
| **FastAPI** | API 优先、原生异步、自动 OpenAPI/Swagger、Pydantic 校验 | 认证/权限需自建 | ✅ **选用** |
| Django | 自带 Admin、成熟 RBAC、`django-auth-ldap` | 偏重、偏服务端渲染 | 备选 |
| Flask | 轻量灵活 | 认证/校验/文档均需自组装 | 不选 |

理由:API 需求明确(且数据源 Baserow 本身是 HTTP API);LDAP/OIDC 均为网络 I/O;类型安全;认证后端可插拔。

### 2.2 前端:Vue3 + Vite + TypeScript + Tailwind CSS v4

组合式 API、极速构建、类型约束、原子化 CSS;配合 Pinia(状态)与 Vue Router(路由/守卫)。

### 2.3 依赖管理:PDM

`pyproject.toml` 声明依赖、`pdm.lock` 锁定版本,保证可复现;团队偏好(相对 uv 更熟悉)。

### 2.4 数据库:SQLite(开发阶段)

零配置、单文件;经 SQLAlchemy 2.0 抽象,后期仅改 `DATABASE_URL` 即可切 PostgreSQL。新增列由 `app/db/migrate.py` 以 `ALTER TABLE` 兜底(无 Alembic)。

## 4. 后端设计

### 4.1 分层架构

```
路由层 (api/routes) —— HTTP 处理、参数校验、权限依赖
   ↓
依赖层 (api/deps)   —— get_current_user / require_permission / get_current_admin / get_current_manager
   ↓
业务层 (crud, services) —— 数据访问与外部集成(baserow / auth / oidc)
   ↓
模型层 (models)     —— ORM
   ↓
数据库 (db/session) —— 连接与会话
```

`schemas` 负责进出数据结构(Pydantic),与 ORM 解耦;`core` 放配置与安全工具。

### 4.2 配置管理(`app/core/config.py`)

使用 `pydantic-settings` 从环境变量 / `.env` 读取,`lru_cache` 缓存单例。主要分组:

| 分组 | 关键项 |
| --- | --- |
| 基础 | `PROJECT_NAME`、`API_V1_PREFIX`、`SECRET_KEY`、`ALGORITHM`、`ACCESS_TOKEN_EXPIRE_MINUTES`、`DATABASE_URL`、`CORS_ORIGINS` |
| 认证后端 | `AUTH_BACKENDS=["local","ldap"]` |
| LDAP/AD | `LDAP_ENABLED/SERVER/BIND_DN/BIND_PASSWORD/BASE_DN/CONNECT_TIMEOUT/AUTO_PROVISION/USE_STARTTLS/TLS_INSECURE/CA_CERT/GROUP_ROLE_MAP` |
| OIDC | `OIDC_ENABLED/ISSUER/CLIENT_ID/CLIENT_SECRET/SCOPES/REDIRECT_URI/POST_LOGIN_REDIRECT/USERNAME_CLAIM/NAME_CLAIM/EMAIL_CLAIM/GROUPS_CLAIM/GROUP_ROLE_MAP/VERIFY_SSL/CA_CERT/COOKIE_SECURE` |
| 引导/统计 | `BOOTSTRAP_ADMIN_*`、`ONLINE_WINDOW_MINUTES`、`LAST_SEEN_UPDATE_SECONDS` |
| 头像 | `AVATAR_DIR`、`AVATAR_MAX_MB` |
| Baserow | `BASEROW_ENABLED/URL/TOKEN/TABLES/DEPARTMENT_FIELD/SOURCES/USER_EMAIL/USER_PASSWORD/WORKSPACES/VERIFY_SSL/CA_CERT` |

### 4.3 安全设计

- **密码**:`passlib` + **bcrypt** 单向哈希、自带加盐。
- **令牌**:`pyjwt` 签发 **JWT**(`sub`=用户名,含 `exp/iat`),无状态,前端持有。
- **时间**:所有时间字段按 **UTC** 序列化(带 `Z`),前端 `new Date()` 自动换算本地时区。见 `app/schemas/common.py::UTCDatetime`。

### 4.4 数据模型

**用户 `users`**

| 字段 | 说明 |
| --- | --- |
| `id` / `username` / `email` / `full_name` / `hashed_password` | 基础信息 |
| `department` | 部门(取自部门管理;数据范围与可见性依据) |
| `is_active` / `is_superuser` | 启用 / 超级管理员 |
| `auth_source` | `local` / `ad` / `oidc` |
| `created_at` / `last_login_at` / `last_seen_at` | 时间;`last_seen_at` 用于在线统计 |
| `avatar_ext` / `avatar_updated_at` | 头像文件扩展名与版本 |

**权限与角色**

| 表 | 说明 |
| --- | --- |
| `roles` | 角色:`code/name/description`、`is_system`(内置不可删)、`is_admin`(管理员)、`is_department_manager`(主管) |
| `permissions` | 权限点:`resource:action` |
| `role_permissions` | 角色→权限 + `data_scope` |
| `user_permissions` | 用户→权限(直接授权)+ `data_scope` |
| `user_roles` | 用户↔角色 |

**其它**:`departments`(部门)、`baserow_sources` / `baserow_tables`(数据源配置)、`demo_records`(演示数据范围)。

### 4.5 认证体系(可插拔)

```
api/routes/auth.py
   └─> services/auth/authenticate()            # 按 AUTH_BACKENDS 顺序尝试
          ├─ LocalAuthProvider (bcrypt 本地校验)
          └─ LdapAuthProvider  (AD 绑定验证)
OIDC 走独立路由 services/oidc.py(授权码 + PKCE,BFF 模式)
```

- **本地/AD**:账号密码登录,失败返回 401;账号禁用 403;AD 不可达 503;来源冲突 409。本地账号保留为 break-glass。
- **AD**:服务账号搜索用户 DN → 用用户 DN+密码重新 bind;支持 `sAMAccountName`/`UPN`/`DOMAIN\user`;`memberOf` → 角色;`userAccountControl` 判断禁用;生产用 `ldaps://` 或 StartTLS。
- **OIDC**:后端中转授权码 + PKCE(见 §7),验证通过后签发本系统 JWT;`groups` claim → 角色。
- **JIT 开通**:`upsert_external_user()` 首次登录自动建本地用户,同步邮箱/姓名/角色。

### 4.6 RBAC 权限与数据范围

- **模型**:用户(直接授权 ∪ 角色授权)→ 权限;权限带**数据范围** `all > dept > self`。
- **有效权限**:`effective_permissions(user)` 返回 `{code: scope}`;超级管理员拥有全部(scope=all)。
- **鉴权依赖**:`require_permission(code)`、`get_current_admin`(超管或管理员角色)、`get_current_manager`(超管/管理员/主管)。
- **`/me` 返回**:`permissions`、`permission_labels`(中文名)、`role_names`、`is_admin`、`manage_scope`。
- **管理层级** `management_scope(user)`:`all`(超管/管理员)、`dept`(主管)、`None`。

### 4.7 部门与主管部门级管理

- **部门配置化**:`departments` 表由管理员维护;用户编辑时部门为下拉;重命名同步更新用户。
- **角色类型**:`is_admin`、`is_department_manager`。预置角色:管理员 `admin`、主管 `supervisor`、运维 `ops`、开发 `dev`。
- **主管权限**:仅可见/可管本部门员工;可给本部门员工分配角色与页面权限;不可授予管理员/主管角色、不可授予管理类权限(`user`/`role` 资源,已有的保留);不可跨部门;不能改角色/部门配置。授超管仅限超管。

## 5. 前端设计

### 5.1 状态与 API 客户端

- `stores/auth.ts`(Pinia):`user`、`token`(localStorage 持久化)、`isAdmin`、`isSuperuser`、`manageScope`、`canManageUsers`、`hasPermission()`、`scopeOf()`、`login/loadUser/acceptToken/logout`。
- `api/client.ts`(axios):请求拦截器自动附加 `Bearer`;响应 401 自动清 token 跳登录。

### 5.2 路由与菜单

| 路由 | 页面 | 访问控制 |
| --- | --- | --- |
| `/login`、`/oidc-callback` | 登录 / OIDC 回调 | 公开 |
| `/` | 主页(个人信息、头像上传、概览) | 登录 |
| `/department` | 部门空间 | 登录 |
| `/department/data` | 数据看板 | `data:view` |
| `/records` | 演示数据 | `record:view` |
| `/admin/users` | 用户管理 | 管理员或主管 |
| `/admin/roles`、`/admin/departments`、`/admin/baserow` | 角色 / 部门 / 数据源配置 | 管理员 |

`AppLayout` 按 `manageScope`/`hasPermission` 动态渲染菜单;支持 `wide` 版式(数据看板全宽)。

### 5.3 主要页面

- **登录页**:现代深色 + 光晕动效;支持本地账号与「统一身份认证」按钮;无 GPU 环境自动降级(见 §5.4)。
- **主页**:个人资料卡片(头像上传)、用户名/部门/角色/权限(中文)、管理员「用户概览」(已注册/在线/来源,点击在线弹出在线用户列表)。
- **部门空间**:普通用户/主管见本部门员工列表;管理员见「全部部门」并可点击查看各部门成员;功能入口玻璃卡片(「数据看板」跳转数据页)。
- **用户管理**:搜索(用户名/姓名/部门)、新增/编辑/删除、角色与直接赋权(主管受部门级限制)。
- **角色管理 / 部门管理 / 数据源配置**:见 §6。

### 5.4 登录页性能与降级

- 动画仅用 `transform/opacity`(GPU 合成);光晕用 `radial-gradient` 而非模糊滤镜;鼠标视差直写 CSS 变量避免 Vue 重渲染。
- 检测到无 GPU 加速 / 低核 / 系统「减少动态效果」时自动降级为静态轻量版;可用 `?effects=on|off` 强制开关。

## 6. Baserow 数据看板

### 6.1 数据源配置方式(按优先级)

1. **网页配置(推荐,免改 .env)**:管理员在「数据源」页录入数据源(名称/地址/令牌/**可见部门**/**标题字段**)与数据表(表名+表 ID),支持**逐个测试连接**;配置存库(`baserow_sources`/`baserow_tables`)。
2. **用户自动发现**:配置 Baserow 用户账号,自动列出其可见的全部 工作区/库/表。
3. **环境变量**:`BASEROW_SOURCES`(多空间令牌)或单空间 `BASEROW_TOKEN`+`BASEROW_TABLES`。

> 关键约束:Baserow 的**数据库令牌按工作区隔离**(跨空间会 `401 ERROR_NO_PERMISSION_TO_TABLE`);**令牌不能列目录**,只有**用户身份**能列工作区/库/表。

**可见部门**:数据源可设「可见部门」多选(取自部门管理);非全局用户仅能看到所在部门的数据源/表,否则 404。

**标题字段**:可对每张表指定「标题字段」(卡片名称取该字段,留空取首列)。

### 6.2 后端能力(`services/baserow.py` + `routes/data.py`)

- 客户端自动携带令牌 / 用户 JWT(过期自动重登)、结构发现缓存 5 分钟;支持内网自签 HTTPS(`BASEROW_CA_CERT` / `BASEROW_VERIFY_SSL`)。
- 行读取按字段类型选择 Baserow 过滤操作符(`single_select_equal` / `multiple_select_has` / `equal`)。
- 权限:复用 RBAC `data:view/create/edit/delete`;仅允许已配置的表;更新/删除校验归属。

### 6.3 前端交互(`views/DataView.vue`)

左侧「工作区→库→表」树 → 选中表后进入三步:

1. **筛选编排**:列名以白色标签平铺,点击变色多选,为每个选中列选值(单/多条件组合)。
2. **跳转面板**:展示每个筛选值的**命中计数与占比**、组合命中数。
3. **展示页(全宽)**:
   - 左侧**分布分析**:可切换**柱状/饼状**、可换分组字段,**点击分区下钻筛选**;
   - 右侧**卡片面板**:按**维度**(最外层筛选字段,无筛选取第一列名)分组,每条记录为独立小卡片;**悬停放大**、**点击弹出大面板**查看整行完整信息(可编辑/删除)。
   - 编辑:文本/长文本/数字/日期/单选/多选/布尔;多选以选项 id 列表提交。
   - 颜色:单/多选标签使用 Baserow 官方调色板(40 档 `light-/基础/dark-/darker-`);未知色名按名生成稳定浅色;支持十六进制色值。

## 7. 原生数据平台(动态表,构建中)

方向:数据不再依赖 Baserow,改为**本系统自有的动态数据表**(元数据驱动),数据存 **PostgreSQL**,渲染全部由 Web 完成(Baserow 集成暂保留并存,后续移除)。

**数据模型**(`app/models/data_table.py`)
- `data_tables`:表定义(code 唯一 / 名称 / 说明 / **标题字段** / **是否按部门过滤** / **部门字段**)。
- `data_fields`:字段(key / label / type / required / order / options)。type:`text/long_text/number/date/boolean/single_select/multiple_select`。
- `data_records`:记录 `data`(JSONB,`{字段key: 值}`)+ `owner_username` / `department`(用于数据范围)。

**数据范围**:记录级,复用 RBAC `data:view/create/edit/delete` 的 `all/dept/self`;记录的 `department` 取"部门字段"的值(未配置则取创建者部门);表可关闭部门过滤(公共表)。

**API**
- 管理员定义表:`/api/admin/datatables`(GET/POST/PUT/DELETE)
- 记录读写:`/api/datatables`、`/api/datatables/{code}/records`(GET/POST/PUT/DELETE)、`/api/datatables/{code}/stats`(按字段分组统计)

**基础设施**:容器新增 `postgres:16`(compose `db` 服务 + `db_data` 卷),`DATABASE_URL=postgresql+psycopg2://...`;SQLite 仍可用于本地开发。

**进度**:后端(模型 / 接口 / 数据范围 / PostgreSQL)已完成;前端「数据源配置(建表与字段)」与「数据面板」重构为下一步。

## 8. 内置行情监控系统(basis_monitor 集成)

将独立项目 `basis_monitor`(Flask,基差/跨期价差与证券行情监控、企业微信告警)作为**子应用**整合进本系统,并**移除其自身登录/用户体系**,统一使用本系统的账号与 RBAC。

**内置方式**
- 源码置于 `backend/third_party/basis_monitor/`;`app/monitor_integration.py` 经 `importlib` 以独立模块名加载,FastAPI 用 `WSGIMiddleware` 挂载到 **`/monitor-app`**,前端路由 `/monitor` 以 iframe 内嵌(同端口同域)。
- 其前端模板 API 改为**相对路径**(`api/...`);nginx 将 `/monitor-app/` 反代到后端(SPA 的 `/monitor` 由前端路由处理,避免冲突)。
- 数据目录经 `BASIS_MONITOR_DATA` 指向卷内(`/app/data/monitor`),配置/规则/历史/日志持久化。
- 配置:`MONITOR_ENABLED`(是否挂载)、`MONITOR_START_ENGINE`(是否启动抓取/告警引擎);依赖:`flask`、`requests`、`beautifulsoup4`。

**统一认证与权限桥接**
- 前端登录后把本系统 JWT 同时写入 Cookie(`iis_token`,同源);
- 后端中间件 `app/monitor_auth.py` 拦截 `/monitor-app*` 请求:校验 JWT → 解析用户与**有效权限**(含数据范围)→ 以请求头注入(`X-IIS-User/Role/View-Scope/Edit-Scope/Delete-Scope/Create/Dept-Owners`)给 Flask 子应用;未登录的页面请求重定向到 `/login`,接口返回 401。
- 子应用据此判定身份与可见/可操作范围,不再使用自身登录。

**权限模型**(权限目录新增资源 `monitor`,复用数据范围 `all/dept/self`)
- `monitor:view`(范围 all/dept/self):可见的规则;共享规则(`owner=*`)对所有可见用户可见。
- `monitor:create`:是否可新增规则(新增归属为本人;管理员默认共享)。
- `monitor:edit` / `monitor:delete`(范围 all/dept/self):**可对"本部门任务"还是"仅自己的任务"进行操作**——`all`=全部、`dept`=本部门(含本人)、`self`=仅本人;共享规则仅 `all` 可改。

**入口**:部门空间「功能入口」新增 **行情监控系统** 卡片,页内跳转到 `/monitor`(内嵌 `/monitor-app/`,不再新标签)。

> 提示:行情抓取依赖外部数据源(新浪等),内网需有相应网络出口;告警走企业微信网关。

## 9. OIDC 统一身份认证

**目标**:对接企业统一身份平台(如 Dex / Keycloak),采用 **授权码流程 + PKCE**,后端中转(BFF),验证通过后签发本系统 JWT。

```mermaid
sequenceDiagram
    autonumber
    participant U as 浏览器
    participant API as 后端 /api/auth/oidc
    participant IdP as 身份平台
    U->>API: GET /oidc/login
    API->>API: state/nonce/PKCE,写入临时 Cookie
    API-->>U: 302 跳转 IdP
    U->>IdP: 登录并授权
    IdP-->>U: 302 回 /oidc/callback?code&state
    U->>API: GET /oidc/callback
    API->>IdP: code + code_verifier 换 token
    IdP-->>API: id_token
    API->>API: 校验签名(JWKS)/iss/aud/nonce;JIT 建用户+角色
    API-->>U: 302 到前端 /oidc-callback#token=JWT
```

要点:端点发现缓存、PKCE(S256)、`state`/`nonce` 防重放、JWKS 验签、`upsert_external_user` 复用、`OIDC_GROUP_ROLE_MAP` 组映射、本地账号 break-glass。自签平台证书用 `OIDC_CA_CERT` 或 `OIDC_VERIFY_SSL=false`。前端登录页经 `GET /auth/methods` 动态显示统一认证按钮。

```bash
docker load -i images/iis-images-<版本>.tar
# 修改 .env 的 TAG=<版本>,按需配置 BASEROW_*/LDAP_*/OIDC_*
```

- 后端启动自动建表 + 补列 + 回填(数据不丢);首次启动按 `BOOTSTRAP_ADMIN_*` 建管理员。

### 9.2 发布流程(每轮功能默认执行)

1. **升版本号**(新功能 minor,修复 patch):改 `backend/app/main.py`、`deploy/app/docker-compose.yml`、`docker-compose.deploy.yml`、`.env.example`、`build-and-save.sh`、`README.md`。

3. **容器验证**:`cp .env.example .env && docker compose -f docker-compose.deploy.yml up -d`,确认 healthy 后 `down`。

5. **提交推送**:`git add -A && git commit && git push origin main`。

> `.env`、`*.db`、`dist/`、`data/`、镜像/发布包均在 `.gitignore` 中,不提交。

## 12. 安全注意事项

| 项 | 现状 | 生产要求 |
| --- | --- | --- |
| `SECRET_KEY` | 默认值 | **必须**改为随机强密钥(≥32 字节) |
| Token 存储 | localStorage | 可评估迁移 HttpOnly Cookie 防 XSS |
| 传输 | 开发 HTTP | 生产**必须** HTTPS |
| AD/OIDC/Baserow 证书 | 支持指定内网 CA | 生产用 CA 校验,勿长期 `VERIFY_SSL=false` |
| CORS | 仅本地来源 | 收敛为实际域名 |
| 数据库 | SQLite | 迁移 PostgreSQL,配置连接池 |
| 凭证 | `.env`(gitignore) | 使用专用集成账号,最小权限 |
| 限流 | 无 | 登录接口增加失败次数限制/验证码 |

## 13. 附录:常见问题

**Q:登录有两个接口 `/login` 和 `/token`?**
A:`/token` 为 OAuth2 表单格式,供 Swagger "Authorize";`/login` 接收 JSON 供 SPA;底层复用同一签发逻辑。

**Q:JWT 过期怎么办?**
A:过期需重新登录(401 自动跳登录页);后期可加 refresh token。

**Q:如何从 SQLite 换 PostgreSQL?**
A:`pdm add psycopg2-binary`,改 `DATABASE_URL` 为 `postgresql+psycopg2://user:pwd@host:5432/db`,ORM 代码无需改。

**Q:Baserow 不同空间如何取数?**
A:数据库令牌按工作区隔离,需每空间一个令牌(网页配置多数据源或 `BASEROW_SOURCES`);若要自动列库/表,需配置一个 Baserow 用户账号(用户模式)。

**Q:为什么单/多选颜色显示为灰色?**
A:颜色名需与 Baserow 调色板对应(40 档),或直接返回十六进制;已支持 hex 与全部官方色名,未知色名会按名生成稳定浅色。
